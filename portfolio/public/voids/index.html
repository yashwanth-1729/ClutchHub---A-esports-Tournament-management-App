02The problem with general-purpose AI

Frontier models know a little about everything, and live in someone else’s data centre.

The strongest models are hundreds of billions to a trillion parameters. They run only in the cloud, priced per token, and every prompt carries your code with it. For a company’s private repository, that is often a deal-breaker, and the answers are still often “almost right”.

03The VOIDS hypothesis

Most of a giant model is irrelevant to any single task.

A 20–30B model, trained deeply on one domain and checked by executable tests, can approach frontier performance on that domain while fitting on one workstation. Compare the sizes honestly: mixture-of-experts models store far more parameters than they use per token.

06The technology behind specialization

Not a new giant model. A focused pipeline on an open one.

Every stage uses published, reproducible methods. Click a stage.

Stage 3 · QLoRA / LoRA, distillation, RL

Specialized training

Supervised fine-tuning with low-rank adapters, distillation from stronger teacher models where licenses allow, then reinforcement learning where the reward is a compiler, a type checker and a test suite, not a human opinion.

LoRA[27]

Freeze the base model; train small low-rank matrices added to its layers.

On GPT-3 175B: 10,000× fewer trainable parameters and 3× less GPU memory than full fine-tuning, with no added inference latency.

Less capacity than full fine-tuning for large shifts; the frozen base is still held in 16-bit.

QLoRA[28]

LoRA through a frozen base quantized to 4-bit NF4, with double quantization and paged optimizers.

Fine-tunes a 65B model on one 48 GB GPU and a 33B model on one 24 GB GPU; 16-bit full fine-tuning of 65B needs more than 780 GB.

Slower per step than 16-bit LoRA; quantization approximations can cost some quality.

Distillation[21]

Train the small model on outputs and reasoning traces from a stronger teacher.

DeepSeek fine-tuned Qwen and Llama models on ~800k teacher samples (SFT only, no RL); the 32B distill beats OpenAI o1-mini on several reasoning benchmarks.

Capped by the teacher; teacher licences and terms must allow it.

RL with verifiable rewards[29]

Reward the model only when a compiler, type checker or test suite says it is right.

DeepSWE (RL only, from Qwen3-32B) raised SWE-bench Verified Pass@1 from 23% to 42.2% in 200 steps; DeepCoder-14B rose from 53% to 60.6% on LiveCodeBench v5.

Needs tasks with executable checks and sandboxed environments; rewards can be gamed if tests are weak.

High-quality and synthetic data[30]

Filter hard for quality; generate exercises with known-correct answers.

phi-1 (1.3B), trained on 6B filtered + 1B synthetic tokens, scored 50.6% on HumanEval; DCLM matched stronger baselines with 40% less compute by filtering.

Synthetic data can leak benchmark content and narrow the model’s style.

Continued pretraining[31]

Keep pretraining on a large domain corpus before instruction tuning.

Code Llama continued Llama 2 on 500B code-heavy tokens and reached up to 67% HumanEval.

Expensive (hundreds of billions of tokens) and can erode general ability.

Why contamination control is not optional

  • 8–18% of HumanEval overlaps with the RedPajama and StarCoder pretraining sets, and rephrased test items slip past n-gram decontamination.[60]
  • Models name the buggy file from the issue text alone in up to 76% of SWE-bench Verified cases, against up to 53% on repositories outside the benchmark: a sign of memorization.[61]
  • LiveCodeBench collects new problems continuously, so a model can be scored only on problems published after its training cutoff.[62]

So VOIDS is scored on tasks written after the base model’s release, with n-gram and embedding de-duplication against training data, and every failure reported.

Why weights ≠ peak memory

The KV cache grows with every token of context (0.23 GB per 1K tokens here), and the runtime needs buffers for activations. A model that “is 18 GB” can need far more at long context.

Assumptions: weights = parameters × bits ÷ 8; KV = 2 × layers × KV heads × head dim × bytes × tokens; overhead = 0.8 GB + 6% of weights (runtime and compute buffers). Usable memory: ~66% of unified memory on Macs up to 36 GB and ~75% above (macOS GPU working-set limit), VRAM − 0.5 GB on NVIDIA, RAM − 4 GB for CPU-only. Hypothetical VOIDS sizes reuse the Qwen2.5-32B attention layout (8 KV heads × 128 dims) with the layer count scaled by √(size ÷ 32.8B): an assumption, since no VOIDS architecture is fixed.

11Evaluation

Performance is measured. Not promised.

VOIDS will be judged against the model it started from, on fresh tasks it could not have seen, by code that runs. Benchmarks that leak into training are worthless: OpenAI stopped reporting SWE-bench Verified in 2026 for exactly this reason.

01

Task completion rate

tasks fully solved ÷ tasks attempted

The headline: did the job get done?

02

Code execution success

outputs that run without error ÷ outputs

Plausible-looking code that crashes counts as a failure.

03

Test pass rate

hidden tests passed ÷ hidden tests

Graded by tests the model never saw.

04

Build success rate

next build && tsc --strict succeed ÷ attempts

Production React has to compile and type-check.

05

Latency

time to first token, time to complete

A model that is right but slow loses the developer.

06

Peak memory

max resident memory during the run

Decides which machines can run it at all.

07

Tokens per second

generated tokens ÷ generation time

Measured on named hardware, never quoted from a ceiling.

08

Cost per successful task

(energy + hardware amortization or API spend) ÷ tasks solved

The number a business actually pays.

Every run has four arms

Unchanged base model

The control. VOIDS must beat the exact model it started from, or training added nothing.

VOIDS React

The candidate, evaluated at every precision it ships in (16-bit, 8-bit, 4-bit).

Strong open models of similar and larger size

Same harness, same tasks, same budget: the fair comparison.

Frontier API models

The reference ceiling on the same tasks, reported with their cost per successful task.

Tasks are written after the base model’s release, run in a sandbox (Node 22, the project’s own package manager, Vitest, Playwright, axe-core), sampled at pass@1, with every prompt, output and failure published.

Approach frontier API models on the React suiteAt a fraction of the cost per successful task, measured, not assumed
Stay usable locally4-bit, 32K context, interactive speed on a single 32 GB GPU: measured tokens/s and peak memory
Lose little outside the domainGeneral coding benchmarks re-run to quantify any regression

If VOIDS doesn’t clear these bars against its own base model, the hypothesis is wrong for that domain, and we will say so. These are targets; no VOIDS model has been trained yet.

Where VOIDS React would be used

Target, not a result
  • On-premise coding assistantFor agencies, product companies and IT services firms whose client contracts forbid sending code to third-party APIs.
  • Regulated industriesBanks, insurers, healthcare and government teams building React front ends under DPDP, RBI or sectoral data rules.
  • Pull-request reviewA React-specialist reviewer in CI that checks hooks, accessibility and performance before a human looks.
  • Migration at scaleClass components to hooks, Pages Router to App Router, JavaScript to strict TypeScript, across thousands of files at a fixed hardware cost.
  • Accessibility remediationFind and fix WCAG failures, verified by axe-core rather than by eye.
  • Offline and edgeDevelopers on laptops with poor connectivity, air-gapped networks, and classrooms without cloud budgets.

What could go wrong

  • The base moves fastQwen alone released new ~27–32B open models in April 2025, February, April and August 2026. A specialist must be re-derivable on each new base, or it falls behind a general model that simply got better.
  • Prices keep fallingHosted 20–32B models already cost US$0.02–0.40 per million input tokens. The case for owning hardware rests on privacy, control and volume, not on price alone.
  • Benchmarks can misleadOpenAI stopped reporting SWE-bench Verified in February 2026, citing contamination. VOIDS has to be judged on fresh, held-out, executable tasks.
  • Licences and teachersThe base model’s licence and any teacher model’s terms decide what can be trained, distilled and sold.
  • It might not workSpecialization may not beat the unchanged base model by a meaningful margin. That is exactly what the evaluation is designed to find out.
